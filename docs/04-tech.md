## 1. 사용하는 기술

| 정할 것 | 선택 | 이유 |
|---|---|---|
| 만드는 방식 | **순수 HTML / CSS / JavaScript** | 설치나 빌드 없이 바로 GitHub Pages에 올라가요 |
| 앱처럼 쓰기 | **PWA** | 아이폰 사파리 → 공유 → "홈 화면에 추가"하면 앱 아이콘이 생기고 전체 화면으로 열려요 |
| 데이터·로그인 | **Supabase** (새 프로젝트) | 아이폰·맥북 어디서나 같은 데이터, 이메일 로그인 |
| 그래프 | **Chart.js** | 무료, 도넛·막대 그래프가 쉬워요 |
| 엑셀 | **SheetJS** | 브라우저에서 바로 월별 탭이 있는 .xlsx를 만들어요 |
| B5 PDF | **브라우저 인쇄** | 인쇄용 화면을 B5 크기로 만들고 → 인쇄 → "PDF로 저장" |
| 환율 | **Frankfurter** | 무료, 가입·키 필요 없음, 날짜별 환율, 원화·달러·엔화 모두 있음 |
| 글꼴 | **Pretendard** | 무료, 깔끔한 한국어 글꼴 |

- 라이브러리는 **CDN**(인터넷 주소)으로 불러와요. 설치할 게 없어요.
- 색은 처음부터 **CSS 변수**로 만들어요. 그래야 마지막 단계에서 다크모드를 쉽게 붙일 수 있어요. ([02-design.md](02-design.md) 12번)

## 2. 누가 쓰나요? — 누구나 가입 가능

**다른 사람도 가입해서 쓸 수 있게** 만들어요. 각자 **자기 가계부만** 보여요.

| 항목 | 내용 |
|---|---|
| 가입 | 이메일 + 비밀번호 |
| 이메일 인증 | 가입하면 인증 메일이 와요. 링크를 눌러야 로그인할 수 있어요 |
| 비밀번호 찾기 | "비밀번호를 잊었어요" → 재설정 메일 |
| 회원 탈퇴 | 설정에서 탈퇴하면 **그 사람 데이터를 모두 삭제**해요 |
| 데이터 보호 | 모든 표에 RLS를 걸어서, 로그인한 **본인 데이터만** 읽고 쓸 수 있어요 ([03-data.md](03-data.md)) |
| 개인정보 안내 | 가입 화면에 짧은 안내를 둬요. (무엇을 저장하는지, 탈퇴하면 지워진다는 것) |

**여러 사람이 쓰게 되면서 생기는 것**
- **메일 발송 한도**: Supabase 기본 메일은 한 시간에 몇 통만 보낼 수 있어요. 가입자가 많아지면 인증 메일이 늦게 가거나 안 갈 수 있어요.
  - 처음엔 기본 메일로 시작해요.
  - 사람이 늘면 무료 메일 서비스(예: Resend)를 연결해요.
- **무료 한도**: Supabase 무료 버전은 데이터 500MB까지 저장할 수 있어요. 가계부 글자 데이터는 아주 작아서 수백 명이 써도 충분해요.
- **이미지 사용 권리**: 범고래와 아이콘 이미지가 공개된 앱에 들어가요. 직접 만든 이미지가 아니라면 **공개 사용이 허락된 이미지인지** 확인이 필요해요.

## 3. 화면 하나짜리 앱 구조 (SPA)

페이지를 여러 개 만들지 않고, **`index.html` 하나 안에서 화면을 바꿔 끼워요.** 주소 끝의 `#`으로 지금 화면을 구분해요.

| 주소 | 화면 |
|---|---|
| `#/login` | 로그인 / 가입 |
| `#/home` | 홈 |
| `#/history` | 내역 |
| `#/stats` | 통계 |
| `#/settings` | 설정 |
| `#/add` | 입력 |
| `#/budget` | 예산 입력 |

- 이유: GitHub Pages는 단순한 파일 서버예요. `#` 방식이 가장 문제없이 동작해요.

### 폴더 구조 (예정)

```
budget-app/
├── index.html          ← 앱의 유일한 HTML
├── manifest.json       ← PWA 설정 (앱 이름, 아이콘)
├── sw.js               ← PWA용 (오프라인 화면 등)
├── css/
│   └── style.css
├── js/
│   ├── app.js          ← 시작점, 화면 전환
│   ├── supabase.js     ← Supabase 연결
│   ├── data/           ← 소항목·카드사·은행 목록 (03-data 2번)
│   ├── screens/        ← 화면별 코드 (home.js, history.js …)
│   └── lib/            ← 계산, 날짜, 환율, 내보내기 등
├── assets/
│   ├── orca/           ← 범고래 이미지
│   └── icons/          ← 소항목 아이콘
└── docs/               ← 기획 문서
```

## 4. 개발 · 확인 · 배포 흐름

JLPT 단어장 때와 같은 방식이에요.

```
① 맥북에서 코드 작성
      ↓
② 맥북 미리보기 (http://localhost:3000) 에서 실시간 확인
      ↓
③ GitHub(Yeon70/budget-app)에 올리기
      ↓  자동 (1~2분)
④ GitHub Pages 배포 → https://yeon70.github.io/budget-app/
      ↓
⑤ 아이폰에서 배포 주소로 QA
```

- **미리보기 서버**: 맥북에 기본으로 있는 파이썬으로 띄워요. 설치할 게 없어요.
  - Claude Code가 띄워주면 브라우저에서 `localhost:3000`으로 열려요.
  - 화면을 아이폰 크기로 보려면 브라우저 개발자 도구의 **아이폰 모드**를 써요.
- **아이폰 QA**: 배포된 주소에서 확인해요. 홈 화면에 추가해서 실제 앱처럼 써보는 것까지 해요.
- **Supabase 로그인 주소 등록**: `localhost:3000`과 배포 주소를 둘 다 Supabase에 등록해야 해요. 그래야 인증 메일 링크가 제대로 돌아와요.

### Supabase (새 프로젝트)
개발 첫 단계에서 같이 해요. 순서만 미리 적어둘게요.
1. supabase.com → New project → 이름 `budget-app`, 지역 **Seoul (Northeast Asia)**
2. 데이터베이스 비밀번호는 따로 안전하게 적어두기
3. 표 만들기: 제가 준비한 SQL을 SQL Editor에 붙여넣고 실행
4. Authentication 설정: 이메일 가입 켜기, 사이트 주소 등록 (4번 참고)
5. 프로젝트 주소(URL)와 **공개 키(anon key)**를 앱에 넣기
   - 이 키는 이름처럼 공개돼도 괜찮은 키예요. 데이터는 RLS가 지켜줘요.
   - 반대로 **service_role 키는 절대 앱에 넣지 않아요.**
